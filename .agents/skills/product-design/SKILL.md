# Product Design

Design around decisions users need to make, not around decorative containers.

- Identify audience, jobs, permissions, content hierarchy, and the primary action.
- Reuse existing tokens and components; define only the missing primitives.
- Choose purposeful typography, a varied but restrained palette, and clear density for the domain.
- Specify responsive layout, keyboard flow, focus states, validation, and all async states.
- Keep copy concise and action-oriented; do not replace discoverability with hidden gestures.
- Validate the design in the actual app at desktop and mobile widths.

## Full Workflow

1. Read the product plan and identify audience, jobs, permissions, decisions, and primary action.
2. Audit existing design tokens, typography, component primitives, iconography, content patterns, and breakpoints.
3. Map information architecture and all meaningful states before choosing visual treatments.
4. Produce a small interaction model or wireframe and confirm the intended workflow with the user.
5. Implement semantic structure, responsive layout, accessible controls, and purposeful visual hierarchy.
6. Verify keyboard navigation, focus, contrast, touch targets, reduced motion, and mobile/desktop rendering.
7. Record decisions, open content questions, and follow-up polish in milestone/backlog docs.
