# Milestone Planning

1. Read the product plan, current state, open milestones, and backlog.
2. Compute the gap between the desired product and verified implementation.
3. Propose no more than three milestones, architecture-enabling work first.
4. Give each milestone objective, scope, dependencies, acceptance criteria, and a user-observable exit condition.
5. Ask the user to confirm the order before writing milestone files.
6. Keep proposals checkable as `User does X -> observes Y`; reject vague completion language.
