# Documentation Drift Audit

1. Compare scripts, routes, dependencies, environment variables, and architecture with `docs/tech.md`.
2. Compare shipped behavior and scope with `docs/product-plan.md` and open milestones.
3. Check `AGENTS.md` against source-of-truth docs and project conventions.
4. Identify stale commands, missing states, unrecorded decisions, and undocumented deferred work.
5. Repair the source document first, then regenerate reflections such as `AGENTS.md`.
6. Record unresolved drift in `docs/STATE.md` or `docs/backlog.md`.
