## Architecture Rules

- Read `docs/STATE.md` and the active milestone before coding.
- Keep server state, client state, and UI state distinct.
- Validate external data and keep secrets server-side.

## Verification Rules

- Write failing tests for checkable acceptance criteria first.
- Run focused tests and browser live iteration after changes.
- Include loading, empty, error, permission, responsive, and keyboard states.

## Documentation Rules

- Update the active milestone and `docs/STATE.md` after progress.
- Put deferred work in `docs/backlog.md`.
- Record top-level decisions in ADRs.
